# 用語集（この記事に出てくる言葉を、やさしく説明）

むずかしい言葉が出てきたら、ここで確認してください。
なるべく専門用語を使わずに説明しています。

---

## 1. まず知っておきたい基本

**形態素解析（けいたいそかいせき）**
一言でいうと：日本語の文章を「意味のある最小の単位」に区切ることです。
英語は単語がスペースで区切られていますが、日本語は区切りがありません。
そこで、機械が「ここで区切る」と判断する仕組みが必要になります。
例：「痛みを抑える」→「痛み」「を」「抑える」。

**トークン**
一言でいうと：区切ったあとの、1つ1つのかたまりのことです。
検索では、この「トークン」を単位にして文書を探します。

**トークン化**
一言でいうと：文章をトークンに区切る作業のことです。
形態素解析とほぼ同じ意味で使っています。

**アナライザー**
一言でいうと：トークン化のやり方をまとめた「部品のセット」です。
「区切る人（トークナイザー）」＋「後処理（フィルター）」で構成されます。
Kuromoji や Sudachi は、このアナライザーの一種です。

**品詞（ひんし）**
一言でいうと：その単語の種類のことです。
例：名詞、動詞、助詞（「は」「を」など）。

**機能語（きのうご）／内容語（ないようご）**
機能語：「は」「を」「です」など、それ自体の意味が薄い語。
内容語：「痛み」「炎症」など、検索のキーワードになる意味のある語。
検索では、ふつう機能語を捨てて、内容語だけを残します。

**ストップワード**
一言でいうと：検索から除外する、ありふれた語のことです。
「は」「の」などの機能語がこれにあたります。

**正規化（せいきか）／ NFKC 正規化**
一言でいうと：表記のゆれを、統一した形にそろえる処理です。
例：全角の「３００」→ 半角の「300」。
こうしておくと、書き方の違いだけで検索が外れるのを防げます。

## 2. Kuromoji のアナライザーを作る「部品」

Kuromoji のアナライザーは、いくつかの部品を順番につなげたものです。
（この順番のことを「チェーン」と呼びます。）

**トークナイザー（tokenizer）**
一言でいうと：文章を実際に区切る、中心の部品です。

**フィルター（filter）**
一言でいうと：区切ったあとに、トークンを整える後処理の部品です。
「基本形にそろえる」「不要な品詞を捨てる」などを行います。

**kuromoji_tokenizer**
一言でいうと：Kuromoji の「区切る」部品そのものです。

**mode: search（サーチモード）**
一言でいうと：`kuromoji_tokenizer` の設定の1つで、長い複合語を検索向けに分解します。
例：「関西国際空港」を、関西 / 関西国際空港 / 国際 / 空港 のように出します。
こうすると、「空港」だけで検索しても引っかかりやすくなります。
※これは「設定」であって、アナライザーの名前ではありません。

**kuromoji_search（この記事の自作アナライザー）**
一言でいうと：`kuromoji_tokenizer` を `mode: search` にして作った、この記事オリジナルのアナライザーです。
標準の `kuromoji` と区別するために、この名前を付けました。
Elasticsearch にもともと入っている名前ではありません。
目的は「標準の Kuromoji」と「検索向けに分解した Kuromoji」を比べることです。

**kuromoji_baseform**
一言でいうと：活用した語を「基本形」に戻すフィルターです。
例：「抑えます」→「抑える」。

**kuromoji_part_of_speech**
一言でいうと：助詞・助動詞などの機能語を、品詞を見て捨てるフィルターです。

**ja_stop**
一言でいうと：日本語のストップワードを取り除くフィルターです。

**kuromoji_stemmer**
一言でいうと：長音（ー）などの表記を整えるフィルターです。
例：「コンピューター」と「コンピュータ」の違いを吸収します。

**lowercase**
一言でいうと：英字を小文字にそろえるフィルターです。
例：「NSAIDs」→「nsaids」。

**CJKWidthCharFilter**
一言でいうと：全角・半角の幅をそろえる前処理です。
CJK は「中国語・日本語・韓国語」の意味です。

**icu_normalizer / analysis-icu**
一言でいうと：ICU という仕組みを使って、文字の正規化を行う部品です。
Elasticsearch のアナライザーの中で正規化したいときに使います。

## 3. アナライザーの種類

**Kuromoji（クロモジ）**
一言でいうと：Elastic 公式の、日本語アナライザー（プラグイン）です。
Elasticsearch の日本語検索で、まず標準的に使われます。

**Sudachi（スダチ）**
一言でいうと：Works Applications が作っている日本語アナライザーです。
Elasticsearch では「外部プラグイン」として使います（公式ではありません）。
新語の辞書更新が速いのが特長です。

**Sudachi の A / B / C モード**
一言でいうと：区切りの「粗さ」を選ぶ設定です。
A：いちばん細かく区切る。
C：大きい単位でまとめる（複合語をひとかたまりにしやすい）。
B：その中間。

**MeCab（メカブ）**
一言でいうと：定番の日本語形態素解析器です。
Elasticsearch のプラグインではないため、Python などで前もって区切って使います。

**fugashi（フガシ）**
一言でいうと：MeCab を Python から使いやすくしたライブラリです。
中身は MeCab なので、結果は MeCab と同じです。

**UniDic / IPAdic（辞書の種類）**
一言でいうと：MeCab などが区切るときに参照する「辞書」です。
UniDic：短い単位で区切る傾向があります（カタカナ語も細かく割れやすい）。
IPAdic：比較的まとまった単位で区切る傾向があります。
同じ MeCab でも、どの辞書を使うかで結果が変わります。

**Janome（ジャノメ）**
一言でいうと：純 Python 製の形態素解析器です。
C 言語の MeCab 本体が不要で、導入が簡単なのが特長です。

**Lindera（リンデラ）**
一言でいうと：Rust 言語で書かれた、新しめの形態素解析器です。
速さが特長です。Elasticsearch のプラグインではありません。

## 4. 辞書まわり

**辞書（じしょ）**
一言でいうと：アナライザーが「どこで区切るか」を判断するための語彙データです。

**SudachiDict**
一言でいうと：Sudachi が使う辞書です。数か月おきに新語が追加されます。

**ユーザー辞書**
一言でいうと：自分で単語を登録できる、追加の辞書です。
「この製品名は1語として扱いたい」というときに使います。

**新語・固有名詞・略語**
新語：新しく生まれた言葉。
固有名詞：製品名・地名・人名など。
略語：短縮した言い方（例：NSAIDs）。
これらは辞書に無いと、うまく区切れないことがあります。

## 5. 比較で使う指標・考え方

**Jaccard 係数（ジャッカードけいすう）**
一言でいうと：2つの結果が「どれくらい似ているか」を 0〜1 で表す数値です。
1.0 に近いほど似ています。
計算は「両方に共通する語 ÷ どちらかにある語の合計」です。

**ペアワイズ**
一言でいうと：「総当たり」のことです。
すべての組み合わせで似ている度合いを比べる、という意味です。

**再現率（さいげんりつ／recall）**
一言でいうと：探したい文書を、どれだけ取りこぼさず拾えたか、です。
高いほど「広く拾える」。

**精度（せいど／precision）**
一言でいうと：拾った文書のうち、どれだけが本当に欲しかったものか、です。
高いほど「ズレが少ない」。

**完全一致／部分一致**
完全一致：語がぴったり同じときだけヒットする探し方。
部分一致：一部が合っていればヒットする探し方。

**フレーズ検索**
一言でいうと：語の並び（順番）まで合っているかを見る検索です。

**複合語（ふくごうご）**
一言でいうと：いくつかの語がくっついてできた、長い語です。
例：「関西国際空港」「非ステロイド性抗炎症薬」。

**再現性（さいげんせい）**
一言でいうと：あとで同じ条件をそろえれば、同じ結果を再確認できること、です。
そのために、バージョンや設定を記録します。

## 6. Elasticsearch の仕組み

**インデックス**
一言でいうと：文書を保存して検索できるようにした「入れ物」です。

**マッピング（mappings）／設定（settings）**
マッピング：どのフィールドに、どのアナライザーを使うかの定義。
設定：アナライザーの作り方などをまとめた、インデックスの設定。

**転置インデックス（てんちインデックス）**
一言でいうと：「どの語が、どの文書に出てくるか」を先に一覧にした仕組みです。
これがあるおかげで、全文検索が速く動きます。

**全文検索**
一言でいうと：文章の中身から、語を手がかりに探す検索です。

**_analyze（アナライズ API）**
一言でいうと：「この文章を、このアナライザーで区切るとどうなるか」を確認する機能です。

**match クエリ**
一言でいうと：指定した語で文書を探す、基本的な検索方法です。

**operator（and / or）**
一言でいうと：複数の語をどう扱うかの設定です。
and：すべての語を含む文書だけヒット。
or：どれか1つでも含めばヒット。

**プラグイン**
一言でいうと：Elasticsearch に機能を追加する「拡張パーツ」です。
公式プラグイン：Elastic が提供（例：Kuromoji）。
外部プラグイン：別の団体が提供（例：Sudachi）。

**ノード／クラスタ**
ノード：Elasticsearch の1台（1プロセス）。
クラスタ：複数のノードが集まった全体。

## 7. 実行する環境

**Self-Managed（セルフマネージド）**
一言でいうと：自分で用意して運用する Elasticsearch です。
公式・外部どちらのプラグインも入れられます。

**Elastic Cloud Hosted（ホステッド）**
一言でいうと：Elastic のクラウド上で動く Elasticsearch です。

**Elastic Cloud Serverless（サーバーレス）**
一言でいうと：運用を Elastic に任せる、より手軽なクラウド版です。
Kuromoji などの基本プラグインは最初から使えます。
ただし、外部プラグインや辞書ファイルの追加はできません。
（同義語は、ファイルではなく synonyms API で使えます。）

**Cloud Connect（クラウドコネクト）**
一言でいうと：自前の Elasticsearch を、Elastic Cloud とつなぐ仕組みです。
これを使うと、EIS などのクラウド機能を利用できます。

## 8. 新しい検索と LLM

**セマンティック検索**
一言でいうと：語の一致ではなく「意味の近さ」で探す検索です。
例：「痛み止め」で「ロキソニン」の文書を拾える、というイメージです。

**ベクトル検索**
一言でいうと：文章を数字の並び（ベクトル）に変えて、近いものを探す方法です。
セマンティック検索を実現する土台になります。

**埋め込み（embedding）**
一言でいうと：文章を「意味を表す数字の並び」に変換したものです。

**多言語埋め込み**
一言でいうと：日本語を含む多くの言語に対応した埋め込みモデルです。

**semantic_text**
一言でいうと：Elasticsearch で、意味による検索を手軽に使うための仕組みです。
形態素解析で区切らなくても、意味で探せます。

**EIS（Elastic Inference Service）**
一言でいうと：Elastic が用意した、AI モデルを呼び出すサービスです。
埋め込み・リランク・LLM などを、自前でモデルを入れずに使えます。

**リランク（rerank）**
一言でいうと：検索で拾った結果を、より適切な順に並べ直す処理です。

**LLM（大規模言語モデル）**
一言でいうと：文章を理解・生成できる、大きな AI モデルです。
例：GPT 系や Claude など。

**gpt-oss-120b**
一言でいうと：この記事で参考に使った LLM のモデル名です（EIS 経由で利用）。

**プロンプト**
一言でいうと：LLM への「指示文」です。
「重要語を抜き出して」などのお願いのことです。

**temperature（テンパラチャ）**
一言でいうと：LLM の出力の「ばらつき具合」を決める設定です。
0 に近いほど、毎回ほぼ同じ答えになります。

**キーワード抽出／クエリ理解**
キーワード抽出：文章から重要な語を抜き出すこと。
クエリ理解：ユーザーの検索意図をくみ取ること。
LLM は、こうした「検索の補助」に向いています。
